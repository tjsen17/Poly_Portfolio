# 자수정 — 자소서 첨삭 및 수정 플랫폼

## 플랫폼 페이지 (2026-09-16)

프로젝트 터미널에서 `npm start` 실행 후 `http://127.0.0.1:4317/`에 접속합니다. PowerShell 실행 정책으로 막히면 `npm.cmd start`를 사용하세요. 별도 빌드나 의존성 설치는 필요 없습니다.

- `/`: 서비스 탐색 홈
- `/services`: 키워드 검색 및 분야 필터 (URL에 검색 조건 유지)
- `/services/resume`, `/services/job-fit`, `/services/interview`, `/services/complete`: 서비스 목적별 상세 안내
- `/guide`: 이용 방법과 FAQ
- `/login`, `/signup`: 이메일 로그인·고객 회원가입
- `/request`: 비공개 첨삭 접수
- `/my`: 내 접수 목록·진행 상태·보완 답변·최종 리포트
- `/operator`: 운영자 검토실
- `/workspace`: 문장 다음 첨삭 작업실 (기존 화면은 이 주소로 이동)

선택한 서비스는 작업실의 검토 요청 초깃값에 반영됩니다. 네 서비스는 같은 분석 API를 사용하며 검토 목적을 달리합니다. 입력과 결과는 자동 저장되지 않습니다. 페이지 이동 전 브라우저 경고를 제공하지만 저장 기능을 대신하지는 않습니다.

`frontend/platform/`의 `catalog.js`는 서비스 데이터/필터, `platform.js`는 페이지별 콘텐츠, `platform.css`는 플랫폼 디자인, `page.html`은 공통 화면 골격입니다. 작업실은 기존 `frontend/index.html`과 기능별 모듈을 사용합니다. 서버는 허용된 페이지와 파일만 제공합니다.

로그인 후 고객은 자신의 첨삭 요청만, 운영자는 모든 첨삭 요청을 열람합니다. 계정 권한은 서버에서 검사합니다. 결제와 전문가 입점 기능은 제공하지 않습니다.

기존 로컬 시제품을 프론트엔드와 백엔드로 나누고, 각 폴더 안에서 기능별로 파일을 분리했습니다. 기존 시제품 원본은 그대로 보존했습니다.

## 폴더와 파일 역할

```text
자수정(자소서 첨삭 및 수정 플랫폼)/
├─ frontend/              # 브라우저에서 실행되는 화면과 기능
│  ├─ index.html          # 화면 구조: 자료 입력, 결과 영역
│  ├─ style.css           # 화면 디자인과 모바일 배치
│  ├─ app.js              # 화면 초기화, 분석 요청, 연결 상태
│  ├─ form.js             # 입력 읽기, 글자 수, 예시 입력
│  ├─ api.js              # 백엔드 API 요청 및 오류 처리
│  ├─ report.js           # 결과 표시, 이전 결과 표시, 저장 버튼
│  ├─ sample.js           # 가상 공고·자소서·샘플 리포트
│  ├─ download.js         # 텍스트 파일 다운로드
│  └─ webmcp.js           # 브라우저 AI 도구의 샘플 표시 연결
├─ backend/               # 로컬 서버에서 실행되는 기능
│  ├─ main.mjs            # 서버 시작, 포트와 주소 설정
│  ├─ app.mjs             # 화면 파일 제공, API 경로, 동의·중복 요청 검사
│  ├─ validation.mjs      # 입력 형식과 글자 수 검증
│  ├─ prompt.mjs          # 첨삭·면접 기준과 요청서 생성
│  └─ review.mjs          # 외부 AI 호출과 응답 처리
├─ tests/
│  └─ app.test.mjs        # HTTP·입력 검증·AI 모의 응답·모듈 경로 검사
├─ .env.example           # API 환경 설정 예시(실제 키 없음)
├─ .gitignore             # 비밀 설정 등을 Git에서 제외
├─ package.json           # 실행·테스트 명령
├─ 시작.cmd               # Windows 서버 실행
└─ README.md
```

사진처럼 기능별 파일을 각 폴더 바로 아래에 두었습니다. 데이터는 로컬 JSON 파일에 저장합니다. 기존 화면의 작업명 ‘문장 다음’은 이번 파일 분류 작업에서 변경하지 않았습니다.

## 실행

Node.js 22 이상이 필요합니다. 추가 패키지 설치는 필요하지 않습니다.

1. `시작.cmd`를 더블클릭합니다. 또는 이 폴더에서 `npm.cmd start`를 실행합니다.
2. 브라우저에서 http://127.0.0.1:4317 을 엽니다.
3. 종료할 때 실행 창에서 Ctrl+C를 누릅니다.

이미 이전 시제품이 4317 포트를 사용하고 있다면 해당 시제품을 종료한 다음 실행하세요. `index.html`을 직접 더블클릭하는 방식은 API와 모듈 경로가 연결되지 않으므로 사용하지 않습니다.

테스트: `npm.cmd test` 또는 `node tests/app.test.mjs`.

## 동작 흐름

`시작.cmd → backend/main.mjs → backend/app.mjs → frontend/index.html → frontend/app.js`

- 요청서: `frontend/app.js → api.js → /api/prompt → prompt.mjs → validation.mjs → download.js`
- AI 분석: `frontend/app.js → api.js → /api/review → validation.mjs → review.mjs → report.js`
- 가상 예시: `sample.js → form.js / report.js`

## 설정 및 현재 한계

실제 AI 분석에는 프로젝트 루트의 `.env`에 `OPENAI_API_KEY`, `OPENAI_MODEL` 설정이 필요합니다. 로컬 FreeLLMAPI를 선택하려면 `AI_PROVIDER=freellmapi`, `FREELLMAPI_API_KEY=통합 키`, `FREELLMAPI_MODEL=auto`를 설정하세요. 기본 접속 주소는 `http://127.0.0.1:3001/v1/responses`이며, 로컬 포트가 다르면 `FREELLMAPI_PORT`를 지정할 수 있습니다. FreeLLMAPI는 별도로 실행하고 제공자 키를 등록해야 합니다. `.env.example`을 참고하세요. 기존 비밀 설정은 복사하지 않았습니다.

실제 AI 호출·과금은 이번 작업에 포함하지 않습니다. 테스트의 AI 응답은 모의 응답입니다. 결제, 데이터베이스, 공개 배포, 자율 유지보수는 아직 구현되지 않았습니다.

공개 배포용이 아닌 로컬 시제품입니다. 기존 정적 배포용 `.openai/hosting.json`은 새 폴더 구조의 서버를 배포할 수 없으므로 복사하지 않았습니다.

## 게시판

`/board`에서 글 목록, 검색(제목·내용·닉네임), 자유·질문·정보 분류, 글 작성과 상세 보기를 이용합니다. 상단 게시판 메뉴로 진입할 수 있습니다. 빈 게시판에서 시작하며 예시 게시글을 실제 사용자 글처럼 표시하지 않습니다.

게시글은 `data/posts.json`에 저장되어 서버 재시작 후에도 유지됩니다. 이 파일은 Git과 웹 파일 제공에서 제외됩니다. 로컬 서버 하나를 위한 저장 방식이며, 일반 게시판의 닉네임 인증과 게시글 수정·삭제·댓글은 아직 없습니다. 닉네임은 누구나 입력할 수 있습니다. 작성 중 이동하면 브라우저 경고가 표시되고 저장 실패 시 입력을 유지합니다. 비공개 첨삭은 별도 계정 인증과 권한 검사를 거칩니다. 일반 게시판은 공개 공간입니다.

### 비공개 첨삭 접수와 운영자 검토

1. `/signup`에서 고객 계정을 만들고 로그인합니다.
2. 게시판 또는 상단의 **비공개 첨삭**에서 원문·요청사항을 제출합니다. AI 결과는 선택입니다. 작업실에서 실제 분석 결과를 가져올 수도 있습니다.
3. 고객은 `/my`에서 **접수 완료 → 운영자 검토 중 → 자료 보완 필요 → 최종 리포트 도착** 상태를 확인합니다. 보완 답변을 보내면 다시 접수 상태로 돌아갑니다.
4. 운영자는 `/operator`에서 원문을 확인하고 수정본·수정 이유·보완점을 임시 저장하거나 고객에게 자료 보완을 요청합니다.
5. 최종 확인 후 제출하면 고객이 리포트를 열람·텍스트 다운로드할 수 있습니다. 운영자 초안은 고객에게 노출되지 않으며 최종 제출한 리포트는 수정할 수 없습니다. 동시 수정 충돌은 저장을 거절하므로 입력을 복사한 뒤 최신 상태를 불러오세요.

**운영자 계정 만들기:** 서버를 Ctrl+C로 종료한 상태에서 프로젝트 터미널의 `npm.cmd run create-admin`을 실행합니다. 이메일·표시 이름·10자 이상 비밀번호를 입력합니다. 비밀번호는 화면에 표시되지 않습니다. 이후 `npm.cmd start`로 서버를 시작하고 `/login`에서 로그인하세요. 기본 계정이나 기본 비밀번호는 없으며 일반 회원가입으로 운영자 권한을 얻을 수 없습니다.

`backend/private.mjs`가 인증·권한·비공개 저장·검토 상태를 처리하고 `frontend/platform/private.js`와 `private.css`가 화면을 담당합니다. `backend/create-admin.mjs`는 로컬 관리자 계정 생성 도구입니다.

계정과 접수 자료는 `data/private.json`에 저장되며 Git 및 웹 파일 제공에서 제외됩니다. 비밀번호는 무작위 salt와 scrypt로 해시합니다. 자료 자체는 디스크에서 암호화하지 않으므로 서버 폴더 접근을 제한하고 백업도 비공개로 보관하세요. 서버를 종료한 뒤 `data` 폴더를 백업할 수 있습니다. JSON 저장은 단일 서버 프로세스용이며 운영 중 별도 관리 명령이나 두 번째 서버로 동시 수정하지 마세요.

로그인 세션은 HttpOnly·SameSite=Strict 쿠키로 유지되며 8시간 후 만료하거나 서버 재시작 시 해제됩니다. 로그아웃하면 세션도 폐기됩니다. 비공개 요청은 작성자와 운영자만 조회할 수 있습니다. 요청서로 가져오는 원문과 AI 결과는 현재 탭의 sessionStorage에 임시 보관되고 접수 성공 또는 로그아웃 시 삭제됩니다. 접수 전 탭을 닫으면 임시 자료를 잃을 수 있습니다.

이전 `추가 첨삭 요청` 공개 글은 공개 API와 게시판에서 제외합니다. 원본은 posts.json에 보존하고 운영자 검토실에서만 열람합니다. 기존 닉네임의 실제 소유자를 확인할 수 없어 새 고객 계정에 자동 연결하지 않습니다. 과거 공개 당시의 노출까지 되돌리는 기능은 아닙니다.

현재 범위는 로컬 시제품입니다. 이메일 인증·비밀번호 재설정·온라인 배포·결제·알림 발송은 포함하지 않습니다. 외부 공개 전 HTTPS와 Secure 쿠키, 배포 환경의 인증·저장 정책을 별도로 적용해야 합니다. 이번 변경은 AI API 설정이나 호출 방식을 추가하지 않습니다.
